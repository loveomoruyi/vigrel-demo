Documentation

Ten minutes to a working operator.

Install, choose a model that fits, grant the microphone, and start talking. Everything below works without a network connection once the model is on disk.

Install

macOS

1. Open Vigrel-1.0.0-mac-arm64.dmg
2. Drag Vigrel to Applications
3. First launch: right-click → Open (builds are ad-hoc signed)
4. Choose a model tier; the weights download once
5. Grant microphone access when asked

Windows

1. Run Vigrel-1.0.0-setup-x64.exe
2. SmartScreen: More info → Run anyway (unsigned beta)
3. Launch Vigrel, choose a model tier
4. Allow microphone access in Windows privacy settings

Linux

chmod +x Vigrel-1.0.0-linux-x86_64.AppImage
./Vigrel-1.0.0-linux-x86_64.AppImage
# FUSE missing? install libfuse2, or run with --appimage-extract-and-run

First run

What the app does

  • Starts a local brain on 127.0.0.1:28090.
  • Starts speech services on :28100 and :28120.
  • Creates ~/.jarvis for memory and logs.
  • Leaves the microphone off until you switch it on.
  • Makes no outbound connection.

Voice

Click the mic to listen; click again to stop. While Vigrel speaks it ducks its own input, then resumes. End-of-speech is detected at 700 ms.

MIC ON listening · device default input
MIC OFF silent · stream kept warm, not closed

Your data

Where it lives, and how to remove it

~/.jarvis/long_term_memory.db  facts, sessions, projects
~/.jarvis/logs/  application logs, no transcript archive
~/.jarvis/models/  weights you downloaded
~/.jarvis/voice.json  your chosen voice
# inspect
sqlite3 ~/.jarvis/long_term_memory.db ".tables"
# erase everything
rm -rf ~/.jarvis

Deleting that directory removes memory, preferences and models. There is no server-side copy to request.

Troubleshooting

When something is quiet

The mic is on but it does not hear me

Check the microphone indicator in the window: if it shows listening and the level bars are flat, the OS may have withheld the input device. Quit and relaunch Vigrel; if the log says the audio service could not start a stream, restart the machine's audio daemon (sudo killall coreaudiod on macOS) and relaunch.

Replies are silent, or a different voice speaks

The system voice is the fallback when the audio device cannot start a stream. On macOS this usually means wired-memory pressure from a large model. Move down a model tier, or close other GPU-heavy applications.

macOS says the app is damaged or from an unidentified developer

Builds are ad-hoc signed during the beta. Right-click the app → Open, or xattr -dr com.apple.quarantine /Applications/Vigrel.app. Notarised builds are the next milestone.

The AppImage will not start on Linux

Install FUSE 2 (libfuse2) or run ./Vigrel-*.AppImage --appimage-extract-and-run.

It is slower than the numbers on this site

The published figures are from an M1 Max with 32 GB at 4K context. Machines with less memory bandwidth, or a model sharing memory with a browser, will be slower. Measure with the same prompt before assuming a fault.

Trial and licence

Thirty days, then your choice

Starting

The trial begins the first time you launch Vigrel: 30 days of Pro features, no card, no account beyond an email. Nothing is charged automatically.

Ending

If you do not subscribe, the app goes read-only. Memory, documents and exports stay available; voice, builds and the large model pause. Nothing is deleted.

Offline

The licence is a signed file verified on the machine, with a 14-day offline grace period. An air-gapped site activates from a file you carry in — no phone-home.

After two years

After 24 consecutive months of subscription, the build you have is yours permanently. No further payment and no check-in requirement.

Cloud add-on

When local is not enough

The add-on moves compute, not storage. Your memory file stays on the device; only the current turn's prompt is transmitted. It falls back to the local model when the network is down.
